# Opsy Bot Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sustituir el sugeridor por el asistente Opsy Bot con catálogo comprobado, DeepSeek privado y controles de consumo distribuidos.

**Architecture:** El proveedor selecciona intención e IDs de producto mediante JSON estricto. El servidor vuelve a consultar registros públicos y construye texto, precios y enlaces; no muestra texto libre ni URLs del proveedor como hechos. Cuotas individual/global se reservan en una sola operación D1 atómica.

**Tech Stack:** fetch/AbortController, Zod, D1, React/Radix, Vitest y Playwright; sin SDK IA ni Genkit.

**Spec:** [Diseño aprobado](../specs/2026-10-18-cloudflare-catalogo-opsy-design.md), [coordinador](2026-10-18-cloudflare-catalogo-opsy-plan.md); consume [P1–P6](2026-10-18-cloudflare-datos-plan.md) y contratos [C1–C2](2026-10-18-catalogo-panel-plan.md).

## Global Constraints

Hereda restricciones del coordinador. «No persistir conversaciones en servidor por defecto». «No renderizar HTML del modelo ni enlaces arbitrarios ejecutables.» «Sin clave o sin controles de consumo disponibles, el chat ofrece carta/WhatsApp sin hacer llamadas facturables.» `DEEPSEEK_API_KEY` y `CHAT_RATE_LIMIT_SECRET` son secretos privados, nunca `NEXT_PUBLIC_`.

## Review Focus

O1 prueba cuotas sin débito parcial y día Bogotá. O2 prueba desconexión/timeout, salida inválida y producto cambiado durante respuesta. O3 prueba reinicio que descarta respuestas tardías, foco y fallo recuperable. HTTP simulado verifica ausencia de datos de cuentas/pedidos, claves o identidad en el payload del proveedor.

## O2: Contexto público y API DeepSeek

**Files:** crear `src/lib/chat/{context,provider,service}.ts`, `src/app/api/chat/route.ts`, `tests/lib/{chat-context,chat-provider}.test.ts`, `tests/api/chat.test.ts`; ampliar helpers de pruebas D1/contexto según se necesiten, sin compartir archivos con C3–C5 al mismo tiempo.

**Interfaces:** `getChatPublicContext(message: string): Promise<ChatPublicContext>` proyecta productos activos C2 y configuración pública P4; `ChatPublicContext` contiene `products`, `categories: Array<{id:string;name:string}>`, `configuration` y `truncated:boolean`. Cada producto de contexto proyecta únicamente ID/nombre/descripción/categoría/alcohol/opciones/precios públicos y `available:boolean` (no stock exacto); configuración es `Pick<StoreConfiguration,'businessHours'|'deliveryZones'|'estimatedDeliveryMinutes'> | null`. Contexto JSON máximo 24.000 caracteres, con selección determinista por coincidencia de nombre/categoría/palabras. `selectChatIntent({request,context,configuration,signal}): Promise<ProviderSelection>`, con `ProviderSelection = {intent:'catalog'|'prices'|'no_alcohol'|'delivery'|'unknown'; productIds:string[]}` estricto, únicos, máximo4. `answerChat(request: ChatRequest, options:{headers:Headers; signal:AbortSignal}): Promise<ChatReply>`; `ChatReply = {message:string; products:ChatProductCard[]; links:{menu:'/menu'; whatsapp:string|null}}`. `ChatProductCard` tiene `id/name/description/image/href:string`, `available:boolean` y `sizes: Array<ProductSize & {priceCop:number}>`; href servidor `/menu?product=<id codificado>`. Errores de ruta usan `ChatError = {code:'INVALID_REQUEST'|'BODY_TOO_LARGE'|'RATE_LIMITED'|'UNAVAILABLE'|'TIMEOUT'; message:string; links:{menu:'/menu';whatsapp:string|null}}`. No se publican claves internas ni datos de usuario.
